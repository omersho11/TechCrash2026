# Challenge 3: Speed Loopback Optimization Brief

This document provides a concise summary of the engineering work done to optimize the data transmission link between the DE10-Lite FPGA and the ESP32 DevKit.

---

## 1. Challenge & Objectives
- **Goal**: Transmit 10,000 bytes generated by an LFSR from the FPGA to the ESP32, calculate the checksum (`sum & 0xFF`), send it back over UART, and verify it on the FPGA in the shortest possible time.
- **Constraints**: 
  - Do not modify fixed FPGA infrastructure (LFSR sequence, timer, checksum verification logic).
  - Target latency must be under **2,600 ms** (baseline UART at 9600 baud takes ~10.4 seconds).

---

## 2. Implemented Architecture
To maximize throughput, we replaced the baseline UART protocol with a high-speed SPI link combined with algorithmic compression:

1. **LSB Compression (8x Payload Reduction)**:
   - Because the LFSR shifts by 1 bit per cycle ($b_{k} = \{b_{k-1}[6:0], lsb_k\}$), the sequence can be reconstructed on-the-fly.
   - The FPGA transmits the first byte ($b_0$) in full, followed only by the LSB bits of the remaining 9,999 bytes.
   - This compressed the transmission payload from 10,004 bytes to **1,255 bytes**.
2. **SPI Master on FPGA**:
   - Custom serial SPI Master running at 3.125 MHz (`CLK_DIV = 16`).
   - Drives `CS_N`, `SCLK`, and `MOSI` signals.
3. **SPI DMA Slave on ESP32**:
   - ESP32 hardware SPI slave (`VSPI_HOST` on IOMUX pins: CS=5, SCLK=18, MOSI=23).
   - Reconstructs the original 10,000 bytes on-the-fly and sends the checksum back over UART (TX pin 16 at 921600 baud).

---

## 3. History of Issues & Debugging Steps
During testing, the ESP32 received corrupted data (e.g. `N` was read as `2262892560` instead of `10000`). We solved this via the following debugging cycle:

1. **Signal Glitches & Bouncing**:
   - Detected state machine CS decode glitches during state changes. Fixed by registering `cs_n` and `drive_bus` in `speed_loopback_top.sv`.
   - Tied the SPI transmitter reset to `state == S_IDLE` to handle reset transitions.
2. **Floating Pin Noise**:
   - Since the lines were high-impedance (tri-state) during FPGA resets/programming, the ESP32 CS pin floated low and captured noise as fake SPI clock edges.
   - **Fix**: Enabled internal `INPUT_PULLUP` on ESP32 CS, and `INPUT_PULLDOWN` on SCLK and MOSI.
3. **Last Byte Alignment Bug**:
   - Simulated the exact LFSR stream in Python and found that the final byte (1255th byte) had the 9999th bit shifted to bit 7 instead of bit 6.
   - **Fix**: Modified `spi_tx.sv` to correctly pack the final byte as `{1'b0, tx_data[0], pack_buf[5:0]}`.
